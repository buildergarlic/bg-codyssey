# AI 근태 판정기 (attendance-ai)

출입관리 단말기에서 **출근/퇴근 메뉴를 잘못 고르고 지문을 찍어도**, AI가 실제 지문 시각과
앞뒤 순서·개인별 출퇴근 패턴을 따져 진짜 출근/퇴근을 판정하고 **정확한 근로시간**을 계산합니다.

- 근로시간은 메뉴가 아니라 **실제로 지문을 찍은 시각**으로 계산합니다.
- 메뉴를 잘못 누른 기록은 AI가 **확실할 때만 자동 정정**하고, 애매하면 **담당자 검토 목록**으로 넘깁니다.
- 모든 판정에는 **사람이 읽을 수 있는 근거**가 붙고, 원본 기록은 절대 수정하지 않습니다.
- 담당자가 검토 목록에 확정값을 적어 다시 넣으면 그대로 반영됩니다. (**최종 결정은 사람**)
- 설치할 것 없이 Python 표준 라이브러리만으로 동작하며, 데이터가 **회사 PC 밖으로 나가지 않습니다**.

## 왜 필요한가

| 상황 | 메뉴를 그대로 믿는 기존 방식 | AI 근태 판정기 |
|---|---|---|
| 퇴근 때 '출근'을 누름 | 그날 퇴근 기록 없음 → 담당자가 수작업 확인 | 순서·시각으로 퇴근임을 판단해 자동 정정 |
| 출근 때 '퇴근'을 누름 | 출근 없이 퇴근 → 계산 불가 | 자동 정정 |
| 잘못 누르고 바로 다시 찍음 | 출근 2번 / 퇴근 2번 혼란 | 5분 안의 연속 입력은 1건으로 묶고 마지막 선택을 반영 |
| 자정을 넘는 야간근무 | 날짜가 바뀌어 짝이 안 맞음 | 달력 날짜가 아닌 '출근→퇴근 흐름'으로 묶음, 야간근로시간 별도 계산 |
| 메뉴를 항상 '출근'으로 두고 찍는 사람 | 매일 오류 | 개인별 '메뉴 습관'을 학습해 메뉴 대신 시각·순서를 신뢰 |
| 지문을 아예 안 찍음 | 오류 | 억지로 맞추지 않고 '기록 누락'으로 검토 요청 |

## 빠르게 써 보기

Python 3.9 이상이 있으면 바로 실행됩니다. (엑셀 `.xlsx` 파일을 직접 읽으려면 `pip install openpyxl`)

```bash
cd attendance-ai
```

**① 웹 화면 (권장)** — 브라우저에서 파일을 끌어다 놓으면 끝. 이 컴퓨터(127.0.0.1)에서만 열립니다.

```bash
python -m attendance_ai serve
```

**② 명령줄**

```bash
python -m attendance_ai analyze 출입기록.csv -o 결과폴더
```

**③ 가상 데이터로 시연** (정답과 비교한 성능까지 출력)

```bash
python -m attendance_ai demo -o demo_out
```

예제 입력 파일: [`examples/sample_punches.csv`](examples/sample_punches.csv) (가상 인물·가상 사번)

## 입력 파일

단말기에서 내려받은 CSV(UTF-8 / CP949 자동 인식) 또는 XLSX. 위쪽에 제목 행이 있어도 머리글을 찾아냅니다.

| 필요한 정보 | 자동으로 알아보는 열 이름 (예) |
|---|---|
| 사번 (필수) | 사번, 사원번호, 직원번호, 사용자ID, 카드번호, ID … (없으면 이름으로 구분) |
| 일시 (필수) | 출입일시, 인증일시, 일시, 일자시간 … 또는 **날짜 + 시간** 두 열 |
| 메뉴 | 구분, 출퇴근구분, 근태구분, 모드, 출입구분, 상태 … (없어도 동작) |
| 이름 / 단말기 | 이름, 성명 / 단말기, 출입문, 장치 … (선택) |

- 날짜 표기: `2026-11-02 09:01:23`, `2026.11.02 9:01`, `2026/11/2 오후 6:05`, `20261102180500`, `2026년 11월 2일 09시 15분`, 엑셀 날짜값 등
- 메뉴 값: 출근·퇴근·외출(=퇴근 방향)·복귀(=출근 방향)·IN·OUT·Check-In… 단말기 고유 코드(예: `1`/`2`, `F1`/`F2`)는 뜻이 제조사마다 달라 직접 지정합니다.

```bash
python -m attendance_ai analyze 출입기록.csv --in-values 1 F1 --out-values 2 F2
```

- 열 이름이 특이하면: `--col-emp 사원코드 --col-datetime 발생시각 --col-label 인증구분`
- 읽지 못한 행, 해석하지 못한 메뉴 값은 조용히 버리지 않고 화면·보고서·`model_summary.json`에 모두 보고합니다.

## 결과 파일

| 파일 | 내용 |
|---|---|
| `report.html` | 한눈에 보는 보고서: 요약, 검토 목록, 정정 내역(근거 포함), 직원별 출퇴근 타임라인 |
| `daily_attendance.csv` | 직원·근무일별 출근/퇴근 시각, 실근무·체류·외출·야간근무 시간, 상태, **메뉴 기준 계산과의 차이** |
| `review_queue.csv` | 담당자 확인이 필요한 항목 (아래 '검토 → 확정' 참고) |
| `corrected_punches.csv` | 원본 지문 기록 1행마다 AI 판정·확신도·처리·근거 (원본 행 번호 포함, 감사 추적용) |
| `employee_summary.csv` | 직원별 평소 출근/퇴근 시각, 메뉴 선택 정확도, 정정·검토 건수 |
| `model_summary.json` | 사용한 설정, 읽기 결과, 학습된 모델 요약 |

계산 규칙
- **출근 시각 = 처음 찍은 시각, 퇴근 시각 = 마지막 찍은 시각** (그 사이엔 사업장에 있었으므로)
- **근무일 = 출근한 날짜** (자정을 넘는 야간근무도 하나의 근무)
- **실근무 = 출근~퇴근 구간의 합** (외출 시간 제외, **휴게시간은 공제하지 않음** — 회사 규정에 맞게 급여 단계에서 적용)
- **야간근무 = 22:00~06:00에 해당하는 실근무** (근로기준법 제56조 기준)
- 퇴근 후 4시간 안에 다시 출근하면 '외출 후 복귀', 그 이상이면 새 근무

## 검토 → 확정 → 재분석 (최종 결정은 사람)

1. `review_queue.csv`를 엑셀로 열어 **확정** 열에 `출근` / `퇴근` / `삭제` 중 하나를 적습니다.
   기록이 빠진 경우엔 **추가시각**에 실제 시각(예: `2026-10-12 18:30`)을 적고 확정에 그 종류를 적습니다.
   **메모**는 근거(본인 소명, 팀장 확인 등)로 결과에 남습니다.
2. 같은 원본과 함께 다시 분석합니다.

```bash
python -m attendance_ai analyze 출입기록.csv --confirm review_queue.csv -o 결과폴더_확정
```

담당자가 확정한 기록은 AI가 그대로 따르며(확신도 100%, 처리 `담당자확정`), 그 정보가 주변 기록의
판정에도 반영됩니다. 웹 화면에서도 '담당자 확정 파일'로 올릴 수 있습니다.

## AI는 어떻게 판단하나

각 직원의 지문 기록을 시간 순서대로 놓고, 기록마다 실제 종류(출근/퇴근)를 '숨겨진 상태'로 보는
**은닉 마르코프 모델(HMM)** 로 가장 그럴듯한 해석을 찾습니다. 정답이 표시된 학습 데이터 없이,
기록 자체에서 **EM(Baum-Welch) 알고리즘**으로 개인별 패턴을 스스로 학습합니다.

| 증거 | 내용 |
|---|---|
| 순서 | 출근 다음엔 퇴근, 퇴근 다음엔 출근. 같은 종류가 연달아 나오면 '재입력' 또는 '기록 누락' |
| 시각 | 직원마다 평소 출근하는 시간대 / 퇴근하는 시간대 (야간·교대도 개인 패턴으로 학습) |
| 경과시간 | 출근→퇴근(근무 길이), 퇴근→출근(휴식 길이)의 분포 |
| 메뉴 | 사용자가 고른 메뉴. '틀릴 수 있는 힌트'로만 쓰며, 직원별로 메뉴를 잘못 고르는 비율까지 학습 |

기록이 적은 신규 입사자는 전체 직원 패턴을 참고하도록 해서(베이지안 축소) 과신하지 않습니다.
판정마다 증거별 기여도(로그 오즈)를 `메뉴 -2.6 / 시각 +3.5 / 앞 순서 +6.0 / 뒤 순서 +5.6` 처럼 남겨
**왜 그렇게 판단했는지** 확인할 수 있습니다.

### 처리 기준

| 처리 | 조건 |
|---|---|
| 정상 | 메뉴와 AI 판단이 같고 확신도 80% 이상 |
| 자동정정 / AI판정 | 메뉴와 다르거나 메뉴가 없을 때, 확신도 **95% 이상** + 아래 안전장치 통과 |
| 정정제안 (검토) | 메뉴와 다르지만 확신도가 95% 미만이거나 안전장치에 걸림 |
| 검토필요 | 확신도가 낮거나 다른 해석도 그럴듯함 |
| 담당자확정 | 담당자가 확정한 값 (AI보다 우선) |

### 안전장치 (확률 모델 위에 덧댄 규칙 검증)

확률 모델은 '지문을 아예 안 찍은 경우'를 '메뉴를 잘못 누른 경우'로 오해해 멀쩡한 기록을 뒤집을 수
있습니다. 가상 데이터 검증에서 실제로 발견된 이런 사례를 막기 위해 다음을 함께 적용합니다.

1. **근무 형태 검증** — 정정 결과 한 구간이 16시간을 넘거나, 평소 근무시간(개인 중앙값)의 50% 미만·180% 초과면 자동 정정을 보류
2. **자동 정정 범위 제한** — 빠진 기록 없이 완결되고 이상 징후가 없는 근무 안에서만 자동 정정. 바로 앞뒤(24시간 이내) 근무에 누락·이상이 있으면 출퇴근 짝이 한 칸씩 밀렸을 수 있으므로 함께 검토
3. **다른 해석 검토** — 누락·이상이 있는 직원은 '기록 누락이 30배 드물다면/흔하다면'으로 다시 해석해 보고, 판정이 달라지는데 그 결과도 정상적인 근무라면 두 해석 모두 가능하다고 보고 검토로 넘김
4. **재입력 간격** — 같은 종류가 15~60분 간격으로 두 번이면 '단순 재입력'인지 '외출/복귀 메뉴 오선택'인지 확인 요청

## 성능 (정답이 있는 가상 데이터)

현장 문제를 일부러 섞은 가상 데이터(사무직·유연근무·야간 고정·3교대·주야 12시간 맞교대, 점심 외출,
연속 재입력, 지문 누락 1.2%, '항상 출근만 누르는 사람', 메뉴 없는 단말기 등)로 측정했습니다.
직원 60명 × 30일 × 무작위 10회, 오선택률별 합계입니다.

```bash
python -m attendance_ai benchmark
```

| 평균 메뉴 오선택률 | 메뉴 정확도(기존) | AI 판정 정확도 | 틀린 메뉴 → 자동정정/검토/놓침 | 맞는 기록을 자동으로 틀리게 바꿈 | 기존 방식: 계산 가능한 날 | AI: 자동 처리된 날 | AI 자동 처리 중 틀린 날 | 지문 누락일 → 검토 요청 |
|---|---|---|---|---|---|---|---|---|
| 5% | 93.61% | 99.70% | 1,427 → 1,323 / 101 / 3 | 0건 / 26,917건 | 81.66% | 95.82% | 0일 / 12,337일 | 303 / 306일 (못 잡은 3일 중 3일은 그날 지문 0건) |
| 10% | 91.10% | 99.68% | 2,101 → 1,959 / 140 / 2 | 0건 / 26,996건 | 74.60% | 95.62% | 0일 / 12,338일 | 296 / 298일 (못 잡은 2일 중 2일은 그날 지문 0건) |
| 20% | 85.64% | 99.68% | 3,576 → 3,319 / 245 / 12 | 1건 / 26,946건 | 61.55% | 94.88% | 0일 / 12,353일 | 335 / 341일 (못 잡은 6일 중 4일은 그날 지문 0건) |

- 메뉴만 믿으면 근무일의 18~38%를 사람이 확인해야 하지만, AI 판정 후에는 **4~5%** 만 확인하면 됩니다.
- **사람 검토 없이 자동 처리된 근무일 중 근무시간이 틀린 날은 0일**입니다(약 37,000 근무일).
- 맞게 찍은 기록을 자동으로 틀리게 바꾼 1건은 같은 날 점심 외출과 퇴근 지문을 둘 다 안 찍어, 기록상 '오전만 근무하고 퇴근할 때 메뉴를 잘못 누른 날'과 똑같아 보이는 경우입니다.
- 가상 데이터는 실제 현장과 다를 수 있습니다. 도입 전에 과거 1~2개월치 실제 기록과 담당자가 정정한 내역으로 같은 방식의 비교를 먼저 해 보길 권합니다.

## 한계와 주의사항

- **그날 지문을 하나도 안 찍었거나, 같은 날 두 번 연속 누락한 경우**(예: 오전 출근과 점심 외출을 모두 누락)는
  기록만으로는 휴무·반차와 구분되지 않습니다. 근무표·휴가 데이터와 대조가 필요합니다.
- **주야 12시간 맞교대**처럼 출근·퇴근 시각과 근무·휴식 길이가 같은 근무는 시각만으로는 출근/퇴근을 구분할 수 없어
  메뉴 선택이 유일한 단서입니다. 이런 직원은 메뉴가 없거나 틀리면 검토로 넘어가는 비율이 높습니다.
- 계산된 실근무에는 **휴게시간이 공제되지 않습니다.** 연장·야간·휴일 가산 등 임금 산정은 회사 규정과 법령에 따라 별도로 판단하세요. 이 프로그램은 근태 기록의 정확성을 높이는 도구이며 법률 판단을 대신하지 않습니다.
- 출입·근태 기록은 개인정보입니다. 결과 파일과 보고서는 열람 권한이 있는 담당자만 다루도록 관리하세요.
  웹 화면은 기본으로 이 컴퓨터(127.0.0.1)에서만 열리며, `--host`를 바꾸면 경고를 표시합니다.

## 판정 정책 바꾸기

명령줄 옵션(또는 웹 화면의 '판정 정책 바꾸기')으로 조정할 수 있습니다.

| 옵션 | 기본값 | 의미 |
|---|---|---|
| `--auto` | 0.95 | 자동 정정 최소 확신도 |
| `--review` | 0.80 | 이 확신도 미만은 검토 |
| `--dup-min` | 5 | 이 시간(분) 안의 연속 입력은 1건으로 묶음 |
| `--new-shift-hours` | 4 | 퇴근 후 이 시간 이상 지나 출근하면 새 근무 (미만이면 외출 후 복귀) |
| `--max-interval-hours` | 16 | 출근~퇴근 한 구간 최대 시간 (초과 시 검토) |
| `--repunch-review-min` | 15 | 같은 종류 재입력 간격이 이보다 길면 검토 |

나머지 세부 설정은 [`attendance_ai/config.py`](attendance_ai/config.py)에 설명과 함께 있습니다.
